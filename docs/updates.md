# Updates
Use `sudo apt update` and `sudo apt upgrade` for Debian packages. Hyprland is
provided by official Trixie backports; updates for installed backport packages
follow Debian's backports policy. Read upgrade output before approving changes.
Do not enable Testing or Unstable archives.

Rilex defaults are a local Debian package. Version 0.1 has no hosted Rilex APT
repository or invented signing identity. For builds generated by the attestation-enabled workflow, GitHub's short-lived
OIDC identity signs build provenance without a maintainer private key in CI.
Verify the downloaded package before installing. Use a current GitHub CLI
(tested with 2.97.0). Debian 13's `gh` package is 2.46.0 and lacks the attestation
command, introduced in [2.49.0](https://github.com/cli/cli/releases/tag/v2.49.0).
Obtain a supported verifier using [GitHub's official installation instructions](https://github.com/cli/cli/blob/trunk/docs/install_linux.md), or verify on another Linux, macOS or Windows computer before transferring the package to Rilex. The optional verifier does not require changing Rilex's Debian repositories.

The release includes real `.intoto.jsonl` attestation bundles. Local bundle
verification was tested with an empty GitHub CLI configuration and no GitHub
authentication token:

```sh
gh attestation verify rilex-defaults_0.1.0_all.deb \
  --bundle rilex-defaults_0.1.0_all.deb.intoto.jsonl \
  -R thepeteriley/rilex \
  --signer-workflow thepeteriley/rilex/.github/workflows/build.yml
sudo apt install ./rilex-defaults_0.1.0_all.deb
```

Inspect the verified source revision and install only the published release you
intended to trust. Attestation establishes build origin/integrity, not functional
quality or release approval. Older diagnostic candidates are not attested.
For the ISO, use its path and corresponding `.iso.intoto.jsonl` bundle. Online verification without `--bundle` fetches attestations from GitHub and may require `gh auth login`. SHA-256 checks remain useful for copying,
but a checksum alone does not establish publisher authenticity.
See [GitHub's attestation documentation](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations).
No update is downloaded or executed automatically, and version 0.1 has no
hosted APT archive. Future package revisions must change the Debian version.

Future infrastructure: publish separate suite/component indexes with aptly or
reprepro, sign Release/InRelease using an offline-controlled release key, ship
only its public key in a dedicated keyring package, and scope Signed-By to that
repository. Never commit private keys. CI builds cannot sign public releases
without an explicitly configured protected signing process. Debian sources and
security updates remain independent of this repository.
