# Rilex packages

`build/build-packages.sh` builds `dist/rilex-defaults_0.1.0_all.deb` with Debian's `dpkg-deb`. It contains desktop defaults, original artwork, welcome helpers, and documentation. Foot, Fuzzel and Waybar use Rilex-owned defaults under `/etc/rilex`; launcher wrappers select these unless user-specific configurations exist. Debian vendor conffiles stay owned by their original packages and receive normal upgrades. Files under `/etc` are Debian conffiles, preserving administrator edits on upgrade; per-user settings belong under `$XDG_CONFIG_HOME`.

The package is generated from the tracked `desktop`, `scripts` and `docs` source trees. The live-build overlay (Calamares settings, password locking and live autologin) is deliberately not in this package. Calamares removes its live autologin configuration and installer launchers from the installed target.

Hyprland is not custom compiled: the compositor, portal and locker are pinned official Debian trixie-backports packages in `config/hooks/live/0200-hyprland.hook.chroot`. APT validates Debian archive signatures and the package hashes covered by those signatures. Their Debian package copyright and source information remain installed. No testing or unstable suite is configured. Backports dependencies are resolved by APT using the explicit backports target for that transaction; the base kernel remains stable.

This is a repeatable build recipe, not a claim of bit-identical artifacts. Debian security and stable updates move over time. Each build records installed package versions under `/usr/share/rilex/package-manifest.tsv`. Publishing fully frozen rebuilds would require retaining the signed repository metadata and package payloads, or a reviewed Debian snapshot policy.

A Rilex update repository is not deployed by 0.1. Update Rilex defaults only using a downloaded Debian package after checking its hash against a release manifest from the authenticated GitHub release channel; `sudo apt install ./rilex-defaults_VERSION_all.deb` handles installation. A checksum alone is not a signature. Production signing/deployment must use an operator-owned archive key and signed Release/InRelease metadata; no fictional key identity or private key is included here. Debian security updates continue through Debian's normal signed APT repositories.

The only package diversion is `/usr/lib/os-release`, which the actual Debian `base-files` package ships as a regular data file, not a conffile. Rilex preserves the vendor version at `/usr/lib/os-release.debian`, owns the active release identity, and leaves Debian's `/etc/os-release` symlink and `/etc/debian_version` intact. A base-files update replaces the diverted vendor data without changing the Rilex identity. Removing Rilex defaults restores Debian identity. `tests/test-release-identity.sh` exercises these operations with a genuine base-files package in a disposable dpkg root. The fixture bypasses dependency enforcement because it tests package file ownership, not executable runtime dependencies; production builds keep normal APT enforcement.

Broadcom firmware is a separate provenance case. With live-build's firmware coverage enabled, Debian's signed `contrib` package `firmware-b43-installer` version `1:019-14` runs its own maintainer script to fetch proprietary Broadcom firmware source version `6.30.163.46` from `https://github.com/minios-linux/b43-firmware/releases/download/b43-firmware/broadcom-wl-6.30.163.46.tar.bz2`. This is a network-dependent firmware extraction helper, not a compositor source or an additional APT repository. The package validates the downloaded archive with its embedded SHA-512 value:

```text
0144894fbbb5e8ebab6c423d9bd0f3249be94f2f468a50b8bf721a3b17f1f6e57467c79e87abc8d136bfc92e701ed046885fead892e9a73efa5217d710311ae9
```

The actual emulated Debian build log (`dist/build-frozen.log`, 2026-10-10 18:57 UTC) records the HTTPS download of 7,684,610 bytes followed by `broadcom-wl-6.30.163.46.tar.bz2: OK`, then extraction of `wl_apsta.o`. Rilex leaves this Debian maintainer logic and checksum validation intact. Broadcom firmware retains its proprietary terms; the free extraction utility and Debian helper do not relicense the firmware. Inspect the installed package's copyright notices and the firmware's license before redistribution for other purposes. Broadcom radio behavior remains hardware-unverified.
